# 训练完成后推荐闭环设计规格

日期：2026-08-19

状态：已确认

适用仓库：`agent2026-interview-agent`

## 1. 背景与目标

个性化训练 Agent 一期已经能够把训练报告异步转换为能力画像和下一步推荐，但用户完成训练后仍停留在报告页。现有报告页没有统一入口查看新推荐，首页也只在首次挂载时请求一次 Dashboard。由于证据同步使用 `AFTER_COMMIT + @Async`，用户立即返回首页时可能短暂看到旧推荐。

本期补齐以下用户闭环：

```text
训练完成
-> 查看复盘报告
-> 查看下一步训练
-> 首页等待最新推荐
-> 按推荐参数进入目标模块
```

目标是让用户在报告之后自然进入下一次训练，同时继续保持 Agent 故障不影响四个训练模块。

## 2. 范围

### 2.1 本期包含

- 知识练习、项目深挖、算法口述和综合模拟报告提供统一的“查看下一步训练”入口。
- 报告入口通过受控路由参数通知首页刷新推荐。
- 首页在训练完成返回场景中执行有上限的短轮询，并显示自然语言同步状态。
- 页面离开时取消未完成的等待，不在后台继续轮询。
- Dashboard 请求失败时保留原有模块入口，并提供一次手动重试能力。
- 增加路由、刷新状态、成功、超时和失败场景的前端测试。

### 2.2 本期不包含

- 把 Agent 重算改为同步阻塞训练完成接口。
- 暴露同步状态、证据 ID、内部能力分或推荐规则动作。
- 自动创建或自动开始下一场训练。
- 自适应选题、个性化综合模拟或语音输入。
- 修改训练报告领域模型和数据库结构。

## 3. 方案比较

### 3.1 仅增加返回首页按钮

改动最小，但无法处理异步同步延迟，用户可能看到旧推荐，不能证明闭环完成。

### 3.2 训练完成接口同步重算

能够立即返回新推荐，但会把 Agent 故障和延迟传播到训练主事务，违背一期的故障隔离原则。

### 3.3 报告入口加首页有界刷新

保持后端异步隔离，前端仅在明确的训练完成返回场景中短暂刷新。请求次数有限、失败可降级，能够以较小改动完成真实用户闭环。本期采用此方案。

## 4. 前端架构

新增 `training-agent` 前端模型层工具，负责：

- 生成统一的训练完成首页路由；
- 识别和清理一次性刷新参数；
- 执行可取消、次数受限的 Dashboard 刷新；
- 返回 `idle / refreshing / settled / failed` 等页面状态。

报告页只负责生成入口，不直接调用 Agent API。首页负责拉取和展示 Dashboard，不让报告模块依赖 Agent 内部状态。

## 5. 数据与时序

```text
报告页 CTA
-> /?refreshTrainingAgent=1
-> HomeView 首次请求 Dashboard
-> 若是训练完成返回场景，按短间隔最多补两次请求
-> 每次成功都替换当前 Dashboard
-> 刷新窗口结束后清理一次性 query
```

默认请求上限为三次：立即请求、约 600ms 后请求、约 1800ms 后请求。它覆盖通常的异步事务提交延迟，同时避免长期轮询和额外服务器负载。

## 6. 页面状态

- 普通进入首页：沿用单次 Dashboard 请求。
- 训练完成返回：显示“正在整理本次训练结果”，刷新完成后显示推荐。
- 刷新窗口结束但推荐未变化：继续展示最后一次可用推荐，不声称已经发生变化。
- 请求失败：显示简短降级提示和手动重试按钮，四个模块入口继续可用。
- Agent 关闭：隐藏推荐区，不继续轮询。

页面不展示 revision、同步任务、证据数量、内部能力分或系统动作。

## 7. 异常与恢复

- 任一次请求成功后都保留可用 Dashboard，后续请求失败不清空已有推荐。
- 页面卸载或离开首页时取消计时器，不继续发送请求。
- 手动重试只启动一个新的有界刷新窗口，重复点击不能并发创建多个轮询。
- 401 继续由现有 HTTP/JWT 刷新机制统一处理，不在 Agent 模块重复实现认证恢复。

## 8. 测试与验收

- 四类报告都存在统一 CTA，并路由到带刷新标记的首页。
- 普通首页访问只请求一次 Dashboard。
- 训练完成返回最多请求三次，页面卸载后停止。
- 新请求结果能够替换旧推荐；后续失败时仍保留最后一次成功结果。
- 失败状态显示手动重试，模块入口数量保持四个。
- query 在消费后被清理，刷新浏览器不会重复触发轮询。
- 现有 Dashboard 状态和推荐参数导航测试全部通过。
- 前端全量测试和生产构建通过。

## 9. 后续阶段

本闭环稳定后进入 Agent 二期自适应选题：首先改造八股 `QuestionSelector`，避免总是按题卡 ID 取第一题，并根据目标维度、历史已答题目和近期薄弱点生成可解释的题目计划。语音输入排在自适应选题闭环之后。
