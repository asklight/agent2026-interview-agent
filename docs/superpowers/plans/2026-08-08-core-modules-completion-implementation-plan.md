# 基础模块补全实施计划

依据：`docs/superpowers/specs/2026-08-08-core-modules-completion-design.md`

## 总体原则

- 按身份与归属、算法口述、训练历史、综合模拟四个可运行阶段推进。
- 每个阶段先补数据库和后端测试，再接前端，最后执行全量回归。
- 保持旧八股和项目深挖接口路径兼容，不做无关重构。
- 外部 LLM 调用不占用数据库长事务。
- 新资源必须校验 JWT 用户归属；旧无归属项目数据继续使用资源令牌。
- 本地学习指南不加入任何提交。

## 阶段一：JWT 身份与用户归属

### 任务 1：认证依赖、配置与数据库

- 在后端增加 Spring Security、JWT 和配置处理依赖。
- 增加 `V4__identity_and_training_ownership.sql`：
  - 创建 `app_user`、`auth_session`；
  - 为 `interview_session`、`project_profile` 增加可空 `user_id`；
  - 增加必要唯一索引、外键和会话轮换约束。
- 增加 JWT issuer、audience、Access/Refresh 有效期、签名密钥和 Cookie 配置。
- 更新 `.env.example`、生产 Compose 和 CI 环境变量。

### 任务 2：identity 后端模块

- 建立用户和认证会话领域模型、仓储端口与 MyBatis 实现。
- 实现用户名规范化、密码策略、BCrypt 哈希。
- 实现 Access/Refresh JWT 签发和验证。
- 实现 Refresh Token 哈希存储、原子轮换、退出撤销和 token family 重放撤销。
- 实现注册、登录、刷新、退出、当前用户接口。
- 为认证接口增加独立错误码和限速边界。

### 任务 3：请求认证与用户归属

- 建立 Bearer Token 过滤器和认证主体解析。
- 配置公开接口与受保护接口边界。
- 将八股会话创建和访问绑定当前用户。
- 将新项目档案和项目面试绑定当前用户。
- 对旧 `user_id IS NULL` 项目数据保留资源令牌兼容访问。
- 增加跨用户访问拒绝测试和旧数据兼容测试。

### 任务 4：前端登录态

- 建立认证 API、Pinia store 和启动时刷新流程。
- Axios 请求自动附加 Access Token。
- 实现单飞刷新和请求最多重放一次。
- 增加登录、注册页面和受保护路由守卫。
- 在应用壳层增加当前用户与退出入口。
- 增加认证 store、Axios 刷新和路由保护测试。

### 阶段一验收

- 两个用户无法互访训练数据。
- 页面刷新后可以通过 Refresh Cookie 恢复登录。
- 退出后 Refresh Token 立即失效。
- 旧项目资源令牌链路仍可用。
- 后端测试、前端测试、类型检查和构建通过。

## 阶段二：算法口述训练

### 任务 5：算法题卡和领域模型

- 增加算法表迁移：`algorithm_problem`、`algorithm_session`、`algorithm_turn`、`algorithm_turn_evaluation`、`algorithm_report`。
- 增加幂等算法题种子数据，首批至少 10 题。
- 建立算法会话状态机、阶段策略和访问归属规则。
- 增加领域状态转换、题目选择和幂等测试。

### 任务 6：算法回答处理与报告

- 定义算法 LLM 结构化评价协议和严格校验器。
- 实现短事务登记回答、事务外模型调用、短事务保存结果的流水线。
- 实现 `clientTurnId` 幂等、version 并发控制和失败恢复。
- 实现阶段推进、变体追问、自然收尾和证据化报告聚合。
- 增加合法响应、坏 JSON、超时、重复提交和报告证据测试。

### 任务 7：算法前端闭环

- 增加算法入口、题目筛选和难度选择。
- 建设专注型算法口述室，不显示过程评分和内部动作。
- 增加提交恢复、刷新恢复、主动结束和报告页面。
- 复用 `TEXT/VOICE_TRANSCRIPT` 输入类型，为后续语音保留接口。
- 增加核心组件和 Composable 测试。

### 阶段二验收

- 用户能独立完成一场算法口述训练。
- 面试覆盖澄清、方案、优化、复杂度、边界和追问。
- 报告证据可追溯到真实轮次。
- 两个用户的算法题记录严格隔离。

## 阶段三：统一训练历史

### 任务 8：历史索引后端

- 增加 `training_history` 表和唯一业务会话约束。
- 建立历史公开端口、幂等 upsert 和补偿重建服务。
- 接入八股、项目深挖和算法的创建、状态变化及报告完成事件。
- 实现分页、类型、状态筛选和隐藏接口。
- 增加主流程成功但历史写入失败的补偿测试。

### 任务 9：历史前端

- 增加紧凑历史列表和筛选控件。
- 根据训练类型和状态生成继续训练或查看报告入口。
- 支持隐藏记录和空状态。
- 增加列表映射、筛选和跳转测试。

### 阶段三验收

- 当前用户只能看到自己的训练。
- 三类训练能统一进入历史。
- 未完成训练可继续，已完成训练可查看报告。
- 隐藏不会删除原始对话证据。

## 阶段四：综合模拟面试

### 任务 10：综合编排领域与持久化

- 增加 `simulation_session`、`simulation_stage`、`simulation_report`。
- 建立固定 PROJECT → KNOWLEDGE → ALGORITHM → REPORTING 状态机。
- 定义三个子模块的公开创建、恢复、结束和报告端口。
- 实现子会话幂等创建、阶段推进和中途结束。
- 增加并发推进、重复请求和部分完成测试。

### 任务 11：综合报告

- 聚合各子报告和关键轮次证据。
- 对未完成阶段明确标注，不生成虚假结论。
- 输出跨模块薄弱点和下一轮训练顺序。
- 增加证据引用和部分报告测试。

### 任务 12：综合前端

- 增加综合模拟配置入口和统一面试室。
- 用自然转场切换阶段，不暴露内部编排动作。
- 支持刷新恢复、当前阶段失败恢复和主动结束。
- 增加综合报告页面和关键流程测试。

### 阶段四验收

- 用户可完成项目、八股和算法组成的完整模拟面试。
- 页面刷新和网络重试不会重复创建子会话。
- 综合报告只引用真实完成阶段的证据。
- 综合模拟进入统一训练历史。

## 最终验证与交付

- 执行全部 Maven 测试与 MySQL 集成测试。
- 执行全部 Vitest、`vue-tsc --noEmit` 和 Vite 生产构建。
- 从空数据库和现有数据库分别验证 Flyway 迁移。
- 使用两个账号手工验证用户隔离。
- 完成算法与综合模拟黄金路径端到端测试。
- 检查桌面和移动端页面无溢出、遮挡和文本截断。
- 检查 JWT、密码、Cookie、API Key 和日志没有敏感信息泄露。
- 检查 `git diff --check` 和未跟踪文件边界。
- 分阶段提交，最终推送 GitHub 自动部署分支并检查生产健康状态。
- 学校 GitLab 仅在凭证可用且推送成功时报告同步。
